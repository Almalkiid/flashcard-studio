## Working rules

- Each external post requires approval of its final text, account, destination and attachment. Approval to merge does not authorize posting. No automatic merging.
- Recheck community rules on posting day. Skip rather than work around a prohibition. Do not paste the same post to multiple communities.
- Be available to answer after posting. No unsolicited DMs, bought/incentivized stars, coordinated voting, fabricated accounts, engagement pods or star-for-star exchanges.
- Invite a first-card attempt and useful feedback. Keep the optional star invitation on the repository, not in every community post.
- Never describe the plugin as a drop-in Anki replacement, conflict-proof, manually reviewed by Obsidian, or proven to improve exam scores.
- Stop promotion if a reproducible data-loss/security issue appears; prepare a fix and accurate notice for approval.

## Measurement

Baseline on 15 October: 0 stars, 0 forks, 0 issues; release main.js downloads 28 across 0.12.0 and 0.12.1; Obsidian separately reported 24. Downloads are not installations. Use the timestamped snapshots for subsequent values.

Proposed internal checkpoints (targets, not forecasts): first 5 detailed first-session reports; first 10 voluntary stars; then 25, 50, 100. For each post record URL, approval, time, asset and resulting discussion. Review changes after 24–48 hours but do not attribute every new star to the last post. Do not invent conversion rates without visitor data.

GitHub traffic is unavailable through the connected repository interface. An owner can supply an Insights → Traffic export or run the collector with authorized traffic access. No plugin telemetry is being added.
